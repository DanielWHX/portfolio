# Portfolio vocabulary

- **Profile Card**: the code-rendered personal overview returned for a broad introduction. Portrait, schools, rankings, interests, and experience are owned by the application; the model supplies a short introduction.
- **Contact Card**: the code-rendered contact methods returned for a contact request. Email, phone, GitHub, LinkedIn, and WeChat are owned by the application and sourced from Hongxiang; the model selects the card and supplies a short lead-in.
- **Quick questions**: the same five prompts on the homepage and above the chat composer. Me, Projects, Skills, and Contact return cards; Fun Facts returns grounded text. Projects and Skills overview shortcuts return code-owned cards without an LLM request.
- **Answer reveal**: a frontend visual animation applied after the complete API response arrives, not model streaming. Text remains available to selection and assistive technology; reduced-motion preferences show it immediately.
- **Conversation session**: completed turns and the current draft retained in sessionStorage for the browser tab. Returning through Me resumes the conversation; New chat clears it. Interrupted requests return as drafts, never automatic retries. Restored cards use current approved data and skip entrance animations.
- **Shared profile**: resume facts plus personal details Hongxiang explicitly supplies, currently fitness, an interest in SaaS companies, and approved contact details. An interest is not a claim of business ownership.
- **Portfolio voice**: a first-person AI representation that can discuss general topics while grounding personal claims in the shared profile. It is not a live human chat.
- **School ranking**: a named category and edition with a source URL. National Universities rankings and Graduate Computer Science rankings are separate; CS #5 is not a separate MCS degree ranking.

The homepage's pink character and Fun Facts remain part of the current visual direction. The personal photograph belongs inside the Profile Card.

- **Projects Card**: selected work in chat. Lyntra is the first featured case study; JChatMind is the second working case-study link. Remaining entries are descriptive placeholders with no pretend destinations. Restored sessions rebuild the current card.
- **Lyntra Case Study**: the English /projects/lyntra page, with a captioned local demo, contributions, core workflow, and simplified logical architecture. It distinguishes working rescheduling and task previews from unfinished background replanning and preview acceptance.
- **JChatMind Case Study**: the English /projects/jchatmind page. Five OrbitDesk stages show a native, scrollable reconstruction of JChatMind using curated messages and tool results from the September 27 recording. Each stage contains only its corresponding turn; tool outputs expand, sidebar views show recorded agent/knowledge data, and New chat replays the fixed question without a model request. The follow-up preserves its original equation and exposes the later clarification separately. Full conversation and highlighted handbook sources remain available. Session/message IDs are excluded from the published transcript; only this fictional demo's approved content is included.

- **JChatMind Live Demo**: an optional iframe targeting the original deployed Spring Boot guest app. Enabled only by the server-side `JCHATMIND_DEMO_URL` after real HTTPS/RAG verification. It is not a replacement model handler implemented in the Portfolio Worker. Hosting is still pending; the recorded walkthrough remains available meanwhile.

- **Skills Card**: the compact English skills overview, grouped by capability: Backend & Systems / AI & Agent Workflows / Frontend Development / Data & Storage / Tools & Cloud / Soft Skills. Python and Java backend engineering are the primary focus; Flask and Spring Boot are highlighted. Project evidence belongs in the Projects Card and case studies, not repeated inside Skills. Original resume lists remain available separately from the display groups. The broader toolkit does not imply equal expertise or proficiency ratings. Lists and positioning are shared with the agent from `lib/portfolio/skills-profile.ts`; restored cards always use current data.

- **Open chat layout**: a white full-height conversation column with a centered avatar and composer, without an enclosing panel. Quick questions use colored line icons. Project previews use one portrait-card carousel headed only “Project”; case-study details stay on the linked pages, and unfinished entries have no link.

- **Case-study layout**: compact project name, one-line purpose, and core stack before the demo. Lyntra shows a short contribution summary and expandable workflow/architecture diagrams. JChatMind keeps interactive replay stages and highlighted sources; full conversation, architecture, and accuracy notes are expandable.

- **Guided experience**: the JChatMind project header's “Explore the demo” button expands the original guest app in place. The guest app offers three independent journeys: Choose a plan, Start a trial, Handle an enquiry. Each step explains the task and fills an editable question; the visitor explicitly sends it. Answers and paired tool evidence come from the original runtime. Tutorial progression waits for a completed answer, not a timer or a canned response. The recorded replay stays separate. Without a configured live URL, the entry explicitly shows availability status and links to the replay.
